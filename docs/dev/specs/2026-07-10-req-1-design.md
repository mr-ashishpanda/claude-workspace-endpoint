# Design: req-1 — session-id UX, per-mapping config, image support, npm packaging

Date: 2026-07-10
Source requirement: `docs/req-1.txt`
Repo: `github.com/mr-ashishpanda/claude-workspace-endpoint`

## Goals

Five deliverables, all inside the local-first V1 boundary:

1. Surface the Claude Code session id so the bridge's headless (`claude -p`) sessions
   can be resumed by a human, in a UX-friendly way.
2. Per-mapping option to enable `--dangerously-skip-permissions`.
3. Per-mapping option to choose a model family (sonnet / opus / haiku), latest
   version auto-picked by the CLI.
4. Slack image upload support; unsupported file types get a "not supported" reply.
5. Package the app so it is installable via `npm install` from the (public) GitHub
   repo, with CI that builds/packs on merge and uploads the tarball as an artifact.

## 1. Session id surfacing

The Claude session id already lives on `SessionRecord.claudeSessionId` and appears in
`@claude status`. Two UX additions:

- **First-reply footer.** When a session's Claude id is captured for the first time
  (the first reply in that scope), append a small italic footer to that one reply:
  `_<identity> | <session-id>_`. No footer on subsequent replies (avoids noise).
- **Status resume hint.** `@claude status` gains a `Resume:` line showing
  `cd <workspace> && claude --resume <id>` once a session exists, so a human can
  continue the exact conversation locally.

## 2. `--dangerously-skip-permissions` per mapping

- `Mapping` gains `skipPermissions: boolean` (default `false`).
- `map add`/`map edit` prompt with an explicit warning; default OFF.
- `buildClaudeArgs` appends `--dangerously-skip-permissions` when true.

## 3. Model family per mapping

- `Mapping` gains `model: ClaudeModel` where
  `ClaudeModel = "default" | "sonnet" | "opus" | "haiku"` (default `"default"`).
- `map add`/`map edit` prompt (choose). `default` = let the CLI auto-pick the latest.
- `buildClaudeArgs` appends `--model <family>` unless `default`.

Backward compatibility: `validateMapping` **defaults** the two new fields when absent
so existing `mappings.json` files load without error.

## 4. Image support

### Supported types

Exactly the Anthropic vision set: `image/png`, `image/jpeg`, `image/gif`,
`image/webp`. Everything else (other images, PDFs, docs, archives, …) is unsupported.

### Flow

- `normalizeMessage` accepts the `file_share` subtype and extracts a `files[]` array
  (`id, name, mimetype, url_private`) into `InboundMessage`, plus `hasAttachments`.
- `route` treats attachments as content: a file-only message triggers (subject to the
  same mention/auto gating). Empty text + no attachments still ignored.
- Handler, on an `invoke` decision:
  1. Partition files into supported images vs unsupported.
  2. If any unsupported: post `:warning: File type "<x>" (name) is not supported.`
     (identity-prefixed), listing each.
  3. Download supported images (bot-token auth on `url_private`) into the app data
     dir `<SLACK_CLAUDE_HOME>/media/<message-ts>/<name>`.
  4. Augment the prompt with the absolute image paths and an instruction to view them.
  5. If, after partitioning, there is no text and no supported image (only
     unsupported files), skip the Claude invocation — the notice was already posted.

### Dependencies / seams

- New `FileDownloader` interface (`download(urlPrivate): Promise<Buffer>`); real impl
  in `app.ts` uses `fetch` with `Authorization: Bearer <botToken>`. Injectable so
  handler tests use a fake — no network, no token in tests.
- New `MediaStore` writes buffers under the app data dir and returns absolute paths.
- Manifest (`docs/slack-app-manifest.yml`) gains the `files:read` bot scope.

## 5. npm packaging + CI

- `package.json`: drop `private`, add `"files": ["dist"]`, `"prepare": "npm run build"`
  (builds on git install since `dist/` is gitignored), and repository/license fields.
  `bin.slack-claude` already points at `dist/cli/index.js` (has a shebang).
  Install target: `npm install github:mr-ashishpanda/claude-workspace-endpoint`.
- `.github/workflows/ci.yml`: triggers on `push` to `master` (i.e. on merge),
  `pull_request`, and `v*` tags. Steps: checkout → setup-node 20 → `npm ci` →
  `npm run verify` (typecheck+lint+test) → `npm run build` → `npm pack` →
  `actions/upload-artifact` with the produced `.tgz`.

## Testing / verification

- Unit tests (vitest, TDD) for: `buildClaudeArgs` (model + skip flags), mapping
  validation defaults + round-trip, file partition/supported-type logic, MediaStore
  writes, router attachment handling, handler image flow (download → prompt augment →
  invoke) and unsupported-notice path, first-reply footer, status resume line.
- Integration: extend the real-runner test to assert `--model`/`--dangerously-skip-permissions`
  forwarding.
- End-to-end sanity: run `npm run verify`, `npm run build`, `npm pack`, and drive a
  fake-Slack image message through the handler to observe a downloaded file + augmented
  prompt. `npm install` the packed tarball into a temp dir and run `slack-claude --help`.

## Review-checklist alignment

- Session/scope integrity: session-id surfacing and media keying use existing scope
  keys; no scope-key changes.
- Trigger correctness: attachments respect mention/auto gating in all four combos.
- Local-first: downloads land in the local app data dir; no hosted service. `files:read`
  is the minimal scope for downloads.
- Secret safety: bot token only from creds/env; never logged; not passed to tests.
- Identity: footer, unsupported notice, and status all carry the mapping identity.
- Naming: "the bridge" throughout.
